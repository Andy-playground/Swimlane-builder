# swimlane-builder 中文說明

**一份 SOP 文件 → 一張 draw.io 泳道流程圖，而且同樣的輸入永遠畫出一模一樣的圖。**

英文版在 [README](../README.md)。操作步驟看[使用指南](USAGE.md)（英文），
錯誤碼看[錯誤碼白話對照](CODES-zh.md)。

## 這是什麼

swimlane-builder 幫一份寫好的作業程序畫出它的流程圖。你給它一份 SOP（流程表、編號步驟、
Word 檔都可以），它還你一張可以在 [draw.io / diagrams.net](https://app.diagrams.net)
打開、分享的泳道圖：每個角色或系統一條橫向泳道，步驟由左到右排列，判斷點分岔，
退回重做的線往回指。

過程中沒有人拉方框。AI 模型讀 SOP，寫下流程**發生了什麼**：每一步誰做、哪裡分岔、
哪幾步會退回重做。接著由一支普通的程式算出每樣東西**放在哪裡**：步驟在第幾欄、
泳道多高、方框多寬、每條線怎麼走。

## 為什麼要做這個

手畫流程圖有三個問題，SOP 愈多愈嚴重：

- **同一份程序，兩個人畫出來不一樣。** 一整套 SOP 有幾個作者，就有幾種畫法。
- **改一小步，要重排一大片。** 中間插一個步驟，後面全部要挪，久了就沒人更新圖。
- **圖和文字對不起來。** 沒有東西檢查圖上畫的還是不是文件寫的。

這個工具把「畫」這件事從人手上拿走。人只決定流程是什麼，版面每次都用同一套方法算出來。

## 你會得到什麼

- **不用手排的圖。** 方框依文字大小決定寬度，線走方框之間的空位、不會穿過方框，
  標籤放在不遮住東西的位置。做不到的時候，工具會告訴你。
- **每次結果都一樣。** 同一份輸入產出完全相同的檔案，一個位元都不差。圖可以放進版本控制，
  SOP 改了就重產；圖有變動，一定是流程有變動。
- **順便檢查流程本身。** 畫圖之前，工具會指出走不到的步驟、只有一條出路的判斷點、
  沒宣告的迴圈、長到讀不了的標籤。
- **多份 SOP 共用一套視覺標準。** 顏色、字體、間距都放在主題裡。一整個資料夾的程序可以
  一次產出，換主題就全部換一套樣式。內建兩套：draw.io 粉彩，以及黑白線框。
- **就是一般的 draw.io 檔。** 不用外掛、不用帳號就能開。圖上有圖例、SOP 原本的步驟編號，
  線下、系統、使用者操作三種互動各有線條樣式。
- **不用安裝，資料不外傳。** 產圖程式只需要 Python 3.11 以上，不用 AI、不連網。
  只有「讀 SOP」這一步用到 AI 模型，用哪一個由你決定。

## 適合用在哪裡

適合的情況：

- 程序是一步一步寫的，每步有負責人。有「負責人」欄位和「→ 步驟 N」指向的流程表最合適。
- 手上有很多份 SOP，希望它們看起來是同一套。
- SOP 常改，圖要跟得上。
- 想把圖當文件一樣審閱、做版本管理。
- 已經在用 AI 助理，希望丟一份文件進去就拿回一張完成的圖。

不適合的情況：

- 想自己手動排版，或產出後再微調。要改圖就改流程描述再重產，手改的內容下次重產就沒了。
- 需要的不是泳道流程圖，例如完整的 BPMN、組織圖、架構圖。
- 流程非常長。大約超過 14 欄，整張圖在筆電螢幕上就小到讀不清楚。工具會提醒，
  要不要把 SOP 拆成兩張由你決定。

## 一張圖是怎麼生出來的

| 階段 | 誰做 | 做什麼 |
|---|---|---|
| ① 抽取 | AI 模型 | 讀 SOP，寫成一份結構化的流程描述：有哪些泳道、哪些步驟、怎麼連。這是唯一需要讀懂人話的一步。規則要求它不得自行編造文件沒寫的步驟，不確定的地方會標出來讓你確認 |
| ② 檢查 | 程式 | 檢查這份描述合不合理。錯誤會停下來並說明要改什麼，警告只是建議，圖照樣產出 |
| ③ 算版面 | 程式 | 純幾何計算。欄位依流程順序決定，方框隨文字變寬，方框之間的走道依經過的線數加寬 |
| ④ 輸出 | 程式 | 把算好的位置寫成 draw.io 檔 |

② 到 ④ 是一支普通的程式，沒有 AI 也不連網，所以結果可以重現。

## 怎麼用

有兩種用法，步驟都寫在[使用指南](USAGE.md)。

- **透過 AI 助理。** 這個 repo 已打包成 Skill。把它加進 Claude，或任何能讀檔、能跑 Python 的
  助理，交給它一份 SOP（文字或 `.docx`），確認它整理出來的流程摘要，就會拿到圖。
  打包檔在 [releases 頁面](https://github.com/Andy-playground/Swimlane-builder/releases/latest)。
- **用命令列。** 用任何 AI 模型搭配 repo 裡附的抽取規則產生流程描述，再用產圖程式處理，
  可以一次一份，也可以整個資料夾一起跑。

想先看成果，直接用 draw.io 打開 [`examples/`](../examples) 裡的 `.drawio` 檔。

一條鐵律：**不要手改 `.drawio` 檔。** 要改圖就改流程描述再重產。

## 術語對照

| 名詞 | 白話 |
|---|---|
| **spec** | 流程描述，一份 JSON 檔。它是流程的「劇本」，圖是從它算出來的。分三塊：誰（lanes）、做什麼（nodes）、怎麼接（edges） |
| **lane**（泳道） | 橫的一條，代表一個角色、部門或系統。誰做這步，就放進誰的泳道 |
| **node**（節點） | 圖上一個框。有六種：起點、終點、步驟、判斷、子流程、文件 |
| **edge**（連線） | 兩個框之間的箭頭 |
| **col**（欄） | 節點在第幾欄，決定左右位置。程式自己算；你也可以指定，但指定的是下限，程式判斷該往後挪還是會挪 |
| **feedback**（回頭線） | 退回重做的線。它往回指，會讓流程繞圈，所以一定要標明，否則報 E102 |
| **channel** | 這一步透過什麼發生：系統對系統、人在系統上操作、線下（email、電話）。決定線的顏色和虛實 |
| **step** | SOP 原本的步驟編號（例如 4a、4b），印成框上的小徽章 |
| **note** | 節點的補充說明。標籤放不下的內容和例外情況的來源寫在這裡 |
| **theme**（主題） | 管所有顏色、字體、間距的設定檔。換主題重產就換一套視覺，不用改 spec |
| **lint** | 檢查 spec 的那一步，會印出 E（錯誤）和 W（警告）代碼 |
| **Skill** | 給 AI 助理用的打包檔，裡面有操作指示和產圖程式 |

## 已知限制

- 起點、終點圓圈裡的字太長會凸出圓圈，目前沒有警告。
- 欄數很多（大約 14 欄以上）的流程，在筆電螢幕上看全圖時字會太小。工具會提醒，
  但不會為了塞進螢幕而改變流程的排法。
- 判斷點的兩條分支，如果其中一條走得比較遠，可能在判斷點附近交叉。
- 很短的線上的標籤可能壓到旁邊的圖形。工具會提醒。
- 從下方進入「文件」圖形的箭頭，會停在波浪底邊下面一點的位置。
