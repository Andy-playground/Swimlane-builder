# swimlane-builder 中文說明

**一次就畫對的泳道流程圖，直接產出 draw.io 檔，用你現有的工具就能打開。**

之後會支援更多格式：Mermaid、SVG、Visio。

英文版在 [README](../README.md)。操作步驟、適用情境與已知限制看[使用指南](USAGE.md)（英文），
錯誤碼看[錯誤碼白話對照](CODES-zh.md)。

## 適用的工具

| | |
|---|---|
| **產生圖** | 加了這個 Skill 的 Claude · 任何能讀檔、能跑 Python 的 AI agent · 任何 LLM 加上命令列 |
| **打開成果** | [draw.io / diagrams.net](https://app.diagrams.net) 網頁版或桌面版，以及其他能匯入 `.drawio` 檔的工具 |
| **執行環境** | Python 3.11 以上。不用安裝任何東西，產圖程式不連網 |

## 怎麼用

把流程交給 AI 助理，請它畫泳道圖。它會先給你一份簡短的摘要，說明它理解到的流程；
你確認或修正之後，就拿到 `.drawio` 檔。

可以交給它的內容：

- **RACI 矩陣或流程表（最推薦）。** 參與方、步驟、使用的工具都寫明了，不需要猜。
- **寫好的作業程序。** 編號步驟或 SOP，文字或 `.docx` 都可以。
- **一段話，或一份會議紀錄。** 描述誰做什麼的文字，或是討論流程那場會議的紀錄。
  把這類內容梳理成步驟，正是語言模型擅長的事。

你給的內容有不清楚的地方，助理會問你，不會自己編步驟。

要改圖，告訴助理哪裡變了，它會重畫一張。Skill 和命令列的詳細步驟在[使用指南](USAGE.md)。

## 它自動幫你做的事

泳道、方框、箭頭，每個工具都畫得出來。這個工具還會處理你平常要手動調整的部分：

**排版**

- 方框隨文字變大，泳道隨方框變高。
- 主流程由左到右走一直線，旁支排在它周圍。
- 頁面大小依圖的大小自動選定。

**連線**

- 線不會穿過方框。
- 線不會疊在一起。幾條線走同一個方向時，會並排走。
- 線走轉彎最少的路，彼此交叉也盡量少。
- 把工作退回前面步驟的箭頭會繞到外側，一眼就找得到。
- 線條樣式代表交接的方式：系統對系統、人在系統上操作、線下（email、電話）。

**標籤與標註**

- 「是」「否」的標籤放在自己那條箭頭旁邊，不會蓋住方框或別條線。
- 每個方框標著你文件裡的步驟編號，圖和文字可以對照著看。
- 自動加上圖例。

**畫圖前的檢查**

- 畫圖前先找出流程的漏洞。例如：沒有任何箭頭指向的步驟，或是只有「是」、沒有「否」的判斷。
- 圖太寬、在筆電螢幕上讀不清楚時會提醒你。

**一致性**

- 同一份輸入每次都畫出同一張圖。圖有變，就代表流程有變。
- 所有的圖是同一種樣式。顏色、字體、間距由主題決定，內建兩套主題。
- 一整個資料夾的程序可以一次畫完。

## 術語對照

| 名詞 | 白話 |
|---|---|
| **spec** | 流程描述，一份 JSON 檔。它是流程的「劇本」，圖是從它算出來的。分三塊：誰（lanes）、做什麼（nodes）、怎麼接（edges） |
| **lane**（泳道） | 橫的一條，代表一個角色、部門或系統。誰做這步，就放進誰的泳道 |
| **node**（節點） | 圖上一個框。有六種：起點、終點、步驟、判斷、子流程、文件 |
| **edge**（連線） | 兩個框之間的箭頭 |
| **col**（欄） | 節點在第幾欄，決定左右位置。程式自己算；你也可以指定，但指定的是下限，程式判斷該往後挪還是會挪 |
| **feedback**（回頭線） | 退回重做的線。它往回指，會讓流程繞圈，所以一定要標明，否則報 E102 |
| **channel** | 這一步透過什麼發生：系統對系統、人在系統上操作、線下（email、電話）。決定線的顏色和虛實 |
| **step** | SOP 原本的步驟編號（例如 4a、4b），印成框上的小徽章 |
| **note** | 節點的補充說明。標籤放不下的內容和例外情況的來源寫在這裡 |
| **theme**（主題） | 管所有顏色、字體、間距的設定檔。換主題重產就換一套視覺，不用改 spec |
| **lint** | 檢查 spec 的那一步，會印出 E（錯誤）和 W（警告）代碼 |
| **Skill** | 給 AI 助理用的打包檔，裡面有操作指示和產圖程式 |
