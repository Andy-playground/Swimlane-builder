# swimlane-builder 中文說明

**把供應鏈的 SOP 變成泳道流程圖，幾分鐘就有初稿，不用再花一個下午。**

把流程表或作業程序交給 AI 助理，拿回一份 draw.io 檔：泳道大小、方框位置、連線走法都排好了。
它是一份完成度很高的初稿，不是定稿；剩下想調整的地方，你在 draw.io 裡自己改。

## 為什麼做這個

我的工作是供應鏈的作業程序：採購單、訂艙、出貨、交期。以前把一份程序畫成泳道圖要三到四個小時，
大部分時間花在拉線，以及每次步驟一動就要重新排版。

用這個工具，初稿大約五分鐘。以我自己的經驗，產出來的圖大約九成是對的，剩下的在 draw.io
裡修幾個地方就好。這也是為什麼成果是 `.drawio` 檔而不是一張圖片：最後那一段留給你收尾。

計畫中的輸出格式：Mermaid、SVG、Visio。

英文版在 [README](../README.md)。操作步驟、適用情境與已知限制看[使用指南](USAGE.md)（英文），
錯誤碼看[錯誤碼白話對照](CODES-zh.md)。

## 適用的工具

| | |
|---|---|
| **產生圖** | 加了這個 Skill 的 Claude · 任何能讀檔、能跑 Python 的 AI agent · 任何 LLM 加上命令列 |
| **打開與修改成果** | [draw.io / diagrams.net](https://app.diagrams.net) 網頁版或桌面版，以及其他能匯入 `.drawio` 檔的工具 |
| **執行環境** | Python 3.11 以上，不需要額外套件。AI 助理讀 SOP 時需要它平常的連線；排版這一步本身不連網 |

## 怎麼用

把流程交給 AI 助理，請它畫泳道圖。它會先給你一份簡短的摘要，說明它理解到的流程；
你確認或修正之後，就拿到 `.drawio` 檔。

可以交給它的內容：

- **RACI 矩陣或流程表（最推薦）。** 參與方、步驟、使用的工具都寫明了，需要猜的很少。
- **寫好的作業程序。** 編號步驟或 SOP，文字或 `.docx` 都可以。
- **一段話，或一份會議紀錄。** 描述誰做什麼的文字，或是討論流程那場會議的紀錄。
  把這類內容梳理成步驟，正是語言模型擅長的事。

指示要求助理遇到不清楚的地方要問你，沒把握的步驟要標上 `TODO` 讓你看得到。
它還是有可能讀錯文件，所以才有那份摘要：接受成果之前請先看過。

改圖有兩種方式：告訴助理哪裡變了，它重畫一張；或是你自己在 draw.io 裡改。
重畫不會保留你手動改過的地方，所以手動修改請留到最後。Skill 和命令列的詳細步驟在[使用指南](USAGE.md)。

## 它自動幫你做的事

泳道、方框、箭頭，每個工具都畫得出來。這個工具接手的是最花時間的那些部分：

**排版**

- 方框隨文字變大，泳道隨方框變高。
- 流程由左到右閱讀，旁支排在它周圍。
- 頁面大小依圖的大小自動選定。

**連線**

- 線會繞過方框，不會從中間穿過去。
- 線不會疊在一起。幾條線走同一個方向時，會並排走。
- 它會試不同的排法來減少交叉：好幾條線從方框同一邊出去時的先後順序，以及判斷點的
  「是」和「否」各從哪一邊出去。簡單的流程常常可以完全沒有交叉，複雜的流程還是會有一些。
- 把工作退回前面步驟的箭頭會繞到外側，一眼就找得到。
- 線條樣式代表交接的方式：系統對系統、人在系統上操作、線下（email、電話）。

**標籤與標註**

- 「是」「否」的標籤放在自己那條箭頭旁邊，避開方框和別條線。找不到空位時還是會畫出來，並提醒你。
- 每個方框標著你文件裡的步驟編號，圖和文字可以對照著看。
- 自動加上圖例。

**畫圖前的檢查**

- 畫圖前先找出流程的漏洞。例如：沒有任何箭頭指向的步驟，或是只有「是」、沒有「否」的判斷。
- 圖太寬、在筆電螢幕上讀不清楚時會提醒你。

**一致性**

- 同樣的步驟每次都畫出同一張圖。畫圖的是程式而不是 AI 模型，流程描述沒變，圖就不會變。
- 所有的圖是同一種樣式。顏色、字體、間距由主題決定，內建兩套主題。
- 一整個資料夾的程序可以一次畫完。

## 目前還做不到的事

- 沒辦法消除所有交叉。這裡最複雜的範例有七個判斷點，還有 14 個交叉。
- 超過大約 14 欄的流程，在一個筆電螢幕上沒辦法用讀得清楚的大小顯示。會提醒你，但不會替你重排流程。
- 你在 draw.io 裡手動改過的地方，重新產生時不會保留。

完整清單在[已知限制](USAGE.md#known-limitations)（英文）。

## 術語對照

| 名詞 | 白話 |
|---|---|
| **spec** | 流程描述，一份 JSON 檔。它是流程的「劇本」，圖是從它算出來的。分三塊：誰（lanes）、做什麼（nodes）、怎麼接（edges） |
| **lane**（泳道） | 橫的一條，代表一個角色、部門或系統。誰做這步，就放進誰的泳道 |
| **node**（節點） | 圖上一個框。有六種：起點、終點、步驟、判斷、子流程、文件 |
| **edge**（連線） | 兩個框之間的箭頭 |
| **col**（欄） | 節點在第幾欄，決定左右位置。程式自己算；你也可以指定，但指定的是下限，程式判斷該往後挪還是會挪 |
| **feedback**（回頭線） | 退回重做的線。它往回指，會讓流程繞圈，所以一定要標明，否則報 E102 |
| **channel** | 這一步透過什麼發生：系統對系統、人在系統上操作、線下（email、電話）。決定線的顏色和虛實 |
| **step** | SOP 原本的步驟編號（例如 4a、4b），印成框上的小徽章 |
| **note** | 節點的補充說明。標籤放不下的內容和例外情況的來源寫在這裡 |
| **theme**（主題） | 管所有顏色、字體、間距的設定檔。換主題重產就換一套視覺，不用改 spec |
| **lint** | 檢查 spec 的那一步，會印出 E（錯誤）和 W（警告）代碼 |
| **Skill** | 給 AI 助理用的打包檔，裡面有操作指示和產圖程式 |
